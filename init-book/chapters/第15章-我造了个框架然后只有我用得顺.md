# 第 15 章 我造了个框架，然后只有我用得顺

## 一

官网要改版。

这种事在公司里排不进任何一份周报的标题。它不算项目，算杂活：没有立项会，没有排期表，没有验收会，做完也不会有人开香槟。

官网我前后改过好几版。最后一版之前的几版，都是我用 betterlife 搭的；最后一版我只留了一部分，剩下的交给做前端的那位——但真正用 betterlife 搭系统的人，从头到尾只有我一个。能确认的是那种手感：模板是现成的，栏目拖一拖、样式调一调，一个下午能出来别人两周的活。

上线之后，群里有人说“看着还行”。然后就没了。

我关了电脑，觉得自己像修水管的：家里不漏水了，没人会感谢水管工；只有漏的时候，所有人都会想起他。

过了很久，官网出了个小毛病。第一个被叫的还是我。那一刻我才回过味来：它平时没人提，坏了却第一个被想起。

## 二

这话不是我抬举自己。用 betterlife 那几年，我做的东西一直不太“上台面”：好几版官网、帮助系统、报表系统，还有 redis helper 的前身。按我自己的说法，这些是核心产品的辅助系统——大意是：“虽然不重要，但是却大大地减少了公司的工作量。”

**不重要的系统，往往在偷偷替你省时间。**

“不重要”这三个字很实在：它不背 KPI，不进汇报 PPT，年终总结里也占不了一行。可它一坏，客服答不出问题，运营拿不到数，官网挂在那儿像关了门。省下来的时间从来不在账上，因为它分散在每个人每一天的十分钟里。

这里还有一层，我当时没想明白：这些系统都是用 betterlife 搭的。它从 2010 年那个雏形起步，到 2015 年才成熟；从那时候到现在，用的人只剩我一个，没有任何其他人。原因不复杂——我是它的原作者，知道怎么把它用到最顺，也只有我能往上拓展开发。别人不是不能用，是要先学会我的用法。

**别人不用，不等于它没用；但“只有我用得顺”，是优势，也是陷阱的入口。**

优势是：同样的活，我干得比谁都快。陷阱是：快到最后，所有活都只剩我能干。

## 三

怎么认出这类“不重要但很值钱”的系统？我后来只用三条：

**一、没人催着做，但它一坏所有人都卡住。**
没人立项，说明它不出彩；一坏全卡，说明它在承重。

**二、每个项目都要重复一遍、又没人愿意重复的那段活。**
建表、导数据、配环境、写导出——谁都嫌烦，谁都还得干。这种地方最值得做一次。

**三、做出来不出彩，但做一次能省很久。**
它的收益不体现在上线那天，体现在之后每一次“这次不用再弄了”。省下的是重复，不是惊喜。

认出来之后，还要补一件最不性感的事：**写一页纸的接入说明。** 干什么、怎么接、出错先看哪儿，三行。没有这三行，再好的东西也只能长在作者身上。

说到这儿，得把两件事分开：**造框架和用框架做事，是两件事。** 前者我是作者，产出的是一套规则；后者我只是用户，而且用 betterlife 的，从头到尾只有我一个。两个身份叠在一个人身上，才显得格外顺。

辅助系统说的是“我用它做了什么”；接下来该说“它自己长出了什么”。redis helper 和 bb.report 没有先后，是从 betterlife 演变出来的两条分支——都同源，不是父子。redis helper 干的事很窄：可视化地查、改 Redis 的 key 和 value。从 2015 年到现在，我在做 Java 后端、又顺手折腾 Redis 可视化工具的圈子里，没见过比它更顺手的。这话只限这个圈子；你要是见过更早、更全的，欢迎把仓库地址、发布时间和功能清单摆出来——我接得住。

## 岔开一句：Redis 是一个人写出来的

redis helper 是围着 Redis 做的，顺带说一句它是怎么来的。

Redis 是 2009 年由 Salvatore Sanfilippo 用 C 写出来的。之后的十一年，主要维护者一直是他——那十一年里，维护者那一栏没有第二个名字。2020 年，他公开宣布退到二线，团队在官方博客上发文谢过他；过了几年，他又回来了。

你手机里那些 App 的临时数据，很多就存在这类地方——它把数据放在内存里，专管“现在这一刻”的数字，所以快。

一个人、一个项目、十一年。这三样摆在一起，比任何架构图都说明一件事：一个东西能活下来，靠的往往不是设计得多漂亮，是有人一直在。

这些我当年都不知道。我只知道它快、好用，然后就围着它做了个工具。

后来 AI 那阵，我用 AI 把它又做了一遍。界面和功能基本一致，补的都是我自己用着别扭的几样：key 排序、回收站、批量删除、首页统计、性能评估。底座换了——Rust 写后端，Tauri 做壳，Web 那一版还在，前端是 Vue.js，另外用了 WebSocket。换底座和加功能，是两件事；把它们讲成一件“觉悟”，是我事后给它加的戏。

还有一个旁支得交代：betterlife.front。它是独立的前端框架，给 betterlife 供前端底座和通用模板。现在没用了。我留着它，不是因为舍不得，是因为我还没想清楚它该不该活着。

## 四

用得越顺，我越不需要别人；越不需要别人，这套东西就越只剩下我一个人能碰。

当时我以为这叫各司其职：我用我的，我改我的。很多年以后才看清，那不是分工，是我把钥匙和锁一起交到了自己手上。

顺手这件事还有个副作用：它让“别人上手”变得没必要。我十分钟就改完了，别人花半天也未必改得动；既然有我，谁还会去试？没人试，就长不出第二个人；没有第二个人，这套东西的寿命就只等于一个人的工龄。

省下来的时间是实的，欠下的维护也是实的。账不在一开始收，在后面每一年慢慢收。

那时候我还挺得意：框架成熟了，我也成熟了。直到有一天发现，成熟的东西有个共同点——离了某个人，就转不动。

---

**本章的一句话**：不重要的系统，往往在偷偷替公司省时间；而“只有我用得顺”，是它开始向你收账的信号。

**今天能用的三条**：
1. 列出三件“没人催、但一坏全卡”的东西，看它们现在谁在维护。
2. 给你最顺手的那个内部工具，补一页纸：干什么、怎么接、出错看哪儿。
3. 找一个没碰过它的人，只给这一页纸，看他能不能跑通——卡在哪儿，就改哪儿。
